# Plane Losses That Last, and Proficiency That Grows - Plan

## Problem

计划 `2026-10-10-004` 让熟练度进了战斗，但服务器上没有任何东西让它变化：`aircraft_lv` 只在发放装备时设定。
普通游玩里飞机永远是 0，那份改动看不到效果。查下去还有一个更早的缺口：出击结算只把血量写回数据库，
被击落的飞机战后原样回来，补给也就从不消耗铝土。

## Evidence

**我方现状：**

- `sortie_result.rs` `update_sortie_result_stats`：按快照里的 `friendly_nowhps` 写血量、扣燃弹、加经验；不碰 `onslot_*`。
  战后的机数就在 `SortieBattleSession::friendly[i].ship.api_onslot` 里，没有人取。
- `compose/supply.rs:104`：补飞机的循环只列了第一槽。飞机不减少时这段从不生效，所以没人发现。
- `slot_item` 只有 `aircraft_lv`（0–7）。战斗端按 `api_alv` 查表得内部经验（计划 004）。
- 模拟不建模索敌，`search` 恒为 `[1, 1]`；航空战是否发生看 `packet.kouku`。
- 项目不写数据库迁移（提交 `36da3d2d`）：加列后旧的本地库要重建。

**参考：**

- 触发条件，[wikiwiki 艦載機熟練度](https://wikiwiki.jp/kancolle/%E8%89%A6%E8%BC%89%E6%A9%9F%E7%86%9F%E7%B7%B4%E5%BA%A6)：
  演习不变；0 架的槽不涨；艦戦、艦爆、艦攻、水戦、噴式在航空战涨，水偵、艦偵、飛行艇在索敌涨，水爆两处都涨；
  打空的槽回港后归 0；出击中不生效，回港时结算。等级阈值 `0/10/25/40/55/70/85/100`，上限 120。
- 数值，[航空機の熟練度の成長について](https://cc-jabberwock.hatenablog.com/entry/2023/08/08/211433)
  与其附表（表格 id `1lLRXpfB…` 成长常数、`1tGEtDid…` 计算器，2026-10-10 取）。玩家统计拟合，作者标注为推定：
  - 一次成长判定：`floor(k × (0.5 + 0.044 × r))`，`r` 是 `[0, A−1]` 上的实数；`A` 按内部经验
    0–20 / 20–50 / 50–100 / 100–120 取 `12 / 10 / 8 / 6`。`k` 是机体的成长常数（2–9），附表给了 230 架，中位数 6。
    `k = 2` 时恒为 1，与文章的表一致。
  - 一战的损失：损耗率 `L = 1 − 残机 / 战前机数`。`L = 1` 时归 0；否则 `M = floor(c × 经验 × L)`，
    `c` 在 `L > 0.5` 时为 0.5、否则 0.3，损失落在 `[0.45M, 0.5M]`。
    例：经验 100、40 架剩 36，损失 1.35–1.5；30 架剩 1，损失 21.6–24。与文章的图一致。
  - 每战先减后加。

## Decision

1. 出击战斗结算时把每艘舰战后的机数写回 `onslot_*`。补给补满全部五个槽，每架 5 铝土（原有单价）。
2. `slot_item` 加 `aircraft_exp`（0–120）。`aircraft_lv` 保留，是它的派生值；所有写等级的地方同时写经验
   （按计划 004 的表 `0,10,25,40,55,70,85,120`）。
3. 经验**按战结算**，和血量、舰经验在同一个事务里；等级（`aircraft_lv`，客户端显示与战斗读取的那个）只在回港时
   由经验刷新（`port_view`）。这样同一次出击里后面的战斗不会用到刚变的熟练度，打空归 0 也是回港才生效，与来源一致，
   又不需要在出击会话里累计、在四个结束出口落盘。与来源剩下的差别：每战按上一战之后的经验计算，而不是出击时的值；
   中途断线的出击，已结算的几战会在下次进港时生效。
4. 经验存整数：损失取 `round(M × (0.5 − 0.05 × r))`，`r` 在 `[0, 1)`。附表按实数累计，这里每战差不到 1。
   损耗率用整数算（`c × 经验 × 损失数 / 战前数`），避免 `1 − 36/40` 的浮点误差把 3 算成 2。
5. 成长常数表放进 gameplay crate 的一个源文件，手工维护，文件头写来源。表里没有的机体用中位数 6。
   不进 Codex：那要动资产、解析器、Codex 字段和重建流程，而这张表只有结算这一处读。

## Scope

**不做：**

- 航空队与防空的熟练度；对潜哨戒机、旋翼机（只在该舰做对潜攻击时涨）；噴式强袭那一次额外判定。
- 第 2 舰队：来源说只在敌方也是连合舰队时才涨，而敌连合还没实现，所以护卫队的飞机不涨（损失照算）。
- 战斗端仍按等级查代表值，不读真实经验。
- 侦察机类的损失公式（来源说几乎不发生）；它们只吃「打空归 0」。
- 演习路径不动。
- 战斗模拟分配损失的方式：它把一个阶段的总损失一架一架从机数最多的槽里扣（`kouku.rs` `apply_plane_losses`），
  而实机是每个槽各自按比例损失、小槽最容易打空。损失入库后这个偏差开始影响铝土消耗、各槽的熟练度损失和「打空归 0」
  的发生频率。改它属于战斗模拟，会动基线，另立计划。

## 审查后的修正（2026-10-10）

- 第二类艦偵（`CarrierBasedRecon2`）原先被当成没有熟练度，已补进侦察机一类。
- 装备栏有空槽时，战斗按去掉空槽后的次序读机数，而结算按物理槽写回，两者会错位。现在进战斗前把机数按同样的次序排好，
  结算时放回装备所在的槽。经公开接口装卸装备会在重算时自动压实，造不出空槽，所以这一条没有测试。
- 成长判定的分段取的是这一战开始时的经验（和损失用的是同一个值），不是减损之后的；已在代码里注明。
- 开幕夜战也按一次索敌给侦察机成长，来源没有说明这一点。
- 没有直接断言 `aircraft_exp` 的集成测试：它不在 API 里，测试通过回港后的等级间接验证；无头检查的数据库里确认过数值。
